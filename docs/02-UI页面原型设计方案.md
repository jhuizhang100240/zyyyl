# 智颐云养老系统 UI 页面原型设计方案

> 版本：V1.0  
> 设计对象：后台管理端、家属端微信小程序  
> 设计目标：统一品牌、提升可读性、降低养老场景操作成本  
> 技术载体：RuoYi-Geek Vue 3 管理端、uni-app 家属端

## 1. 设计定位

### 1.1 品牌名称

系统对外统一名称为“智颐云养老”。

品牌释义：

- 智：智能服务、数据辅助和 AI 助手。
- 颐：颐养、照护和健康管理。
- 云：统一数据、多端协同和可持续扩展。

### 1.2 设计关键词

- 温暖可信
- 清晰易读
- 安静专业
- 长者友好
- 家属安心
- 数据可信

### 1.3 设计原则

1. 重要信息优先展示，避免复杂装饰。
2. 状态不只依赖颜色，同时使用文字和图标。
3. 后台管理端强调效率，家属端强调理解和安心。
4. 所有关键操作必须有明确反馈和恢复路径。
5. 长者相关信息使用更清晰的字号、行高和对比度。

## 2. 视觉规范

### 2.1 色彩规范

采用“医疗蓝绿 + 健康绿 + 温暖中性色”的品牌组合。蓝色用于导航和主要操作，绿色用于健康、安全和成功状态，橙色用于提醒，红色仅用于危险操作和严重异常。

| 角色 | 色值 | CSS 变量 | 使用场景 |
| --- | --- | --- | --- |
| 品牌主色 | `#0E7490` | `--color-primary` | 侧边栏选中、主按钮、链接 |
| 品牌深色 | `#155E75` | `--color-primary-strong` | 悬停、标题强调 |
| 品牌浅色 | `#E0F2FE` | `--color-primary-soft` | 选中背景、信息提示 |
| 健康绿色 | `#16A34A` | `--color-success` | 健康、已完成、安全状态 |
| 提醒橙色 | `#D97706` | `--color-warning` | 待处理、即将到期、预约提醒 |
| 风险红色 | `#DC2626` | `--color-danger` | 错误、严重风险、删除 |
| 页面背景 | `#F4F8FA` | `--color-background` | 管理端内容区域 |
| 卡片背景 | `#FFFFFF` | `--color-surface` | 卡片、表格、弹窗 |
| 主要文字 | `#0F172A` | `--color-text` | 标题和正文 |
| 次要文字 | `#475569` | `--color-text-secondary` | 辅助说明 |
| 弱化文字 | `#64748B` | `--color-text-muted` | 时间、提示 |
| 边框 | `#D8E3E8` | `--color-border` | 表格、输入框、分割线 |

颜色约束：

- 正常文本与背景对比度不低于 4.5:1。
- 图表和状态标签不得只使用红绿区分。
- 页面不得使用大面积紫色渐变、霓虹色或低对比度灰色。
- 品牌色可以统一，但后台管理端和家属端可使用不同的信息密度。

### 2.2 字体与排版

| 层级 | 字号 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| 页面标题 | 24px | 32px | 700 | 页面主标题 |
| 卡片标题 | 18px | 26px | 600 | 模块标题 |
| 正文 | 16px | 24px | 400 | 常规内容 |
| 表格正文 | 14px | 22px | 400 | 后台高密度数据 |
| 辅助说明 | 13px | 20px | 400 | 时间、备注、提示 |
| 小程序正文 | 17px | 27px | 400 | 家属端主要内容 |
| 数字统计 | 28px | 36px | 700 | 指标卡数字 |

字体建议：

- 中文：`PingFang SC`, `Microsoft YaHei`, `Noto Sans SC`, sans-serif。
- 英文和数字：`Atkinson Hyperlegible` 作为可读性优先字体。
- 数字统计使用等宽数字特性，避免数据跳动。

### 2.3 圆角、阴影和间距

- 小控件圆角：6px。
- 卡片和弹窗圆角：8px。
- 标签和头像可使用完整圆角。
- 阴影只用于层级区分，不使用大面积发光或模糊装饰。
- 间距采用 4px、8px、12px、16px、24px、32px 的固定序列。

## 3. 后台管理端设计

### 3.1 布局结构

```text
+----------------------+-------------------------------------------+
| 品牌 Logo            | 顶部栏：面包屑、机构、消息、用户          |
| 智颐云养老           +-------------------------------------------+
|                      |                                           |
| 首页                 | 页面标题与操作区                          |
| 老人管理             | 筛选条件                                  |
| 护理管理             | 数据卡片 / 表格 / 图表                    |
| 预约管理             |                                           |
| 健康档案             | 分页与批量操作                            |
| 系统管理             |                                           |
+----------------------+-------------------------------------------+
```

关键尺寸：

- 侧边栏展开宽度：240px。
- 侧边栏收起宽度：64px。
- 顶部栏高度：64px。
- 内容区最大宽度：1440px，超出后用留白控制阅读长度。
- 数据表格页面保持紧凑，表单页面采用两列或三列栅格。

### 3.2 导航结构

| 一级菜单 | 二级菜单 |
| --- | --- |
| 首页 | 工作台、风险提醒、服务统计 |
| 机构管理 | 楼层、房间、房型、床位 |
| 老人管理 | 老人档案、家属绑定、健康评估 |
| 入住管理 | 入住申请、入住记录、合同管理 |
| 护理管理 | 护理等级、护理项目、护理计划、护理任务 |
| 预约管理 | 参观预约、探访预约、预约统计 |
| AI 助手 | 对话、历史记录、知识问答 |
| 系统管理 | 用户、角色、菜单、部门、字典、日志、监控 |

### 3.3 关键页面原型

#### 3.3.1 登录页

页面目标：

- 快速建立“智颐云养老”品牌认知。
- 保持 RuoYi-Geek 登录能力，支持账号密码、验证码和已有登录策略。

页面结构：

- 左侧品牌区：品牌名称、简短说明、养老场景图片或数据化图形。
- 右侧登录卡片：账号、密码、验证码、登录按钮、记住账号。
- 底部：版权信息、隐私说明和备案信息占位。

交互要求：

- 登录按钮提交后进入加载状态，禁止重复提交。
- 错误信息显示在对应字段下方。
- 不在前端显示默认账号或默认密码。

待确认：原系统是否使用微信扫码、短信或邮箱登录，需要按原接口保留。

#### 3.3.2 工作台

页面目标：

- 让管理员在首屏了解机构运行状态。

页面结构：

- 顶部四张指标卡：在住老人、今日护理任务、待处理预约、待处理风险。
- 中部左侧：护理任务完成趋势。
- 中部右侧：老人年龄或护理等级分布。
- 下部左侧：今日任务列表。
- 下部右侧：合同到期和风险提醒。

交互要求：

- 指标卡可点击跳转到对应模块。
- 图表提供文字摘要和空数据状态。
- 风险提醒按严重程度排序，颜色加图标和文本共同表达。

#### 3.3.3 老人档案列表

```text
[老人姓名] [身份证号] [护理等级] [床位状态] [搜索]

[新增老人] [导出]

姓名 | 性别 | 年龄 | 手机号 | 床位 | 护理等级 | 状态 | 操作
张三 | 男   | 82   | 138..  | A-101| 三级护理 | 入住中 | 详情 编辑
```

列表列建议：

- 姓名、性别、年龄。
- 脱敏手机号和身份证号。
- 床位、护理等级、入住状态。
- 最近健康评分和风险等级。
- 操作列：详情、编辑、绑定家属。

#### 3.3.4 床位与房型

页面采用“楼层筛选 + 房间卡片 + 床位状态”的结构。

- 床位状态：空闲、已入住、申请中。
- 悬浮或点击床位显示老人姓名、护理等级和入住时间。
- 危险或不可用床位使用图标和文字，不只依赖颜色。

#### 3.3.5 入住申请

采用分步表单，避免一次性展示过多字段。

```text
步骤 1 选择老人 -> 步骤 2 健康评估 -> 步骤 3 房型床位
-> 步骤 4 合同信息 -> 步骤 5 确认提交
```

关键要求：

- 每一步支持返回修改。
- 提交前展示合同、床位和费用摘要。
- 提交中禁止重复点击。
- 服务端失败后保留用户输入，并给出可恢复路径。

#### 3.3.6 护理任务看板

建议同时提供表格视图和看板视图。

| 视图 | 适用场景 |
| --- | --- |
| 表格视图 | 精确筛选、批量处理、导出 |
| 看板视图 | 主管快速查看待执行、执行中、已超时 |

卡片内容：

- 老人姓名、床位、护理项目。
- 预计服务时间和护理员。
- 状态标签和超时时间。
- 执行、改期、取消三个操作入口。

#### 3.3.7 AI 助手

页面结构：

- 左侧对话列表，支持新建、切换和删除。
- 中部消息区，支持流式文本、加载状态和错误重试。
- 底部输入区，支持回车发送和停止生成。

交互要求：

- AI 输出明确标注“信息辅助，不构成医疗诊断”。
- 查询老人信息时必须由服务端校验权限。
- 历史记录删除需要二次确认。

## 4. 家属端微信小程序设计

### 4.1 信息架构

小程序底部使用 4 个一级入口：

1. 首页
2. 家人
3. 服务
4. 我的

预约、健康、账单、合同、订单等页面从一级入口进入，不放入底部导航。

### 4.2 关键页面原型

#### 4.2.1 登录页

- 品牌名称“智颐云养老”。
- 手机号和验证码登录，或保留原微信登录方式。
- 隐私协议和用户协议使用明确勾选项。
- 登录成功后进入首页。

待确认：原小程序使用的登录接口为 `POST /member/user/login`，需确认是否仍采用手机号密码或微信授权登录。

#### 4.2.2 首页

```text
+----------------------------------+
| 智颐云养老            消息  我的 |
|                                  |
| 家人卡片：张三  82岁  入住中     |
| 床位：A-101      护理等级：三级  |
|                                  |
| 健康摘要：最近评估 82 分  低风险 |
| 下一次预约：2026-10-08 10:00     |
|                                  |
| 快捷入口：预约 护理记录 账单 合同 |
|                                  |
| 最近服务记录                      |
| 09-28 测量血压      已完成       |
+----------------------------------+
```

#### 4.2.3 家人绑定

- 输入老人姓名、身份证号或由机构提供绑定码。
- 绑定前展示隐私说明。
- 绑定成功后刷新家人列表。
- 解绑需要二次确认。

#### 4.2.4 服务与护理进度

- 按时间倒序展示护理项目、服务时间、护理员和执行状态。
- 点击记录查看执行备注和图片。
- 不展示后台内部备注和敏感操作日志。

#### 4.2.5 预约

- 选择参观或探访。
- 选择日期和时段。
- 展示剩余可预约人数。
- 填写预约人、手机号和探访人。
- 提交成功后展示预约编号和状态。

#### 4.2.6 账单、订单与合同

- 账单：费用项目、金额、状态和时间。
- 订单：服务项目、下单时间、订单状态。
- 合同：合同编号、起止日期、状态和协议查看。
- 金额使用等宽数字，状态使用文字和图标。

#### 4.2.7 我的

- 当前家属信息。
- 家人列表。
- 消息通知。
- 隐私设置。
- 退出登录。

## 5. 通用组件规范

| 组件 | 规范 |
| --- | --- |
| 主按钮 | 每页只保留一个主要操作，使用品牌主色 |
| 图标按钮 | 使用现有 Element Plus 图标或统一 SVG 图标集，必须有可访问名称 |
| 状态标签 | 文字 + 图标 + 颜色，避免只用颜色表达 |
| 表格 | 表头固定，支持排序、筛选、空状态和分页 |
| 表单 | 可见标签，必填标识，错误信息位于字段下方 |
| 弹窗 | 标题、内容、主次操作清晰，危险操作使用红色 |
| 加载态 | 超过 1 秒使用骨架屏或明确进度提示 |
| 空状态 | 说明原因并提供下一步操作 |
| 通知 | 不抢占焦点，3 至 5 秒自动消失 |

## 6. 响应式与无障碍

### 6.1 管理端断点

| 断点 | 布局 |
| --- | --- |
| 小于 768px | 侧边栏收起，表格允许横向滚动或切换卡片列表 |
| 768px 至 1023px | 双列表单，侧边栏可折叠 |
| 1024px 至 1439px | 标准后台布局，三列或四列指标卡 |
| 1440px 及以上 | 限制内容最大宽度，增加留白 |

### 6.2 无障碍检查

- 键盘可访问所有主要操作。
- 焦点轮廓清晰，不被固定栏遮挡。
- 表单错误使用 `aria-live` 或等价方式通知。
- 图片提供替代文本。
- 动画可关闭，并尊重 `prefers-reduced-motion`。
- 小程序触控区域不小于 44 x 44px。

## 7. 设计交付物

建议在原型工具中建立以下页面集：

1. 设计令牌页：颜色、字体、间距、圆角、阴影、图标。
2. 通用组件页：按钮、输入框、选择器、表格、标签、弹窗、空状态。
3. 后台核心页面：登录、工作台、老人、床位、入住、护理、预约、AI、系统管理。
4. 小程序核心页面：登录、首页、家人、绑定、服务、预约、账单、合同、我的。
5. 响应式和交互标注页。

## 8. 验收清单

- [ ] 所有页面显示“智颐云养老”或对应品牌短标识。
- [ ] 主要颜色、字体、圆角和间距来自设计令牌。
- [ ] 后台与小程序状态含义一致。
- [ ] 表单、列表、空状态、错误状态和加载状态齐全。
- [ ] 关键页面在 375px、768px、1024px 和 1440px 宽度下检查通过。
- [ ] 不依赖颜色单独表达风险或状态。
- [ ] 长者相关内容满足更大字号和更高对比度要求。
