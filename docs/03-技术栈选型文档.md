# 智颐云养老系统技术栈选型文档

> 版本：V1.0  
> 基准项目：RuoYi-Geek 3.9.1-G  
> 选型原则：复用基准项目、保留业务接口、避免无关框架、控制毕业设计实现复杂度  
> 版本说明：本稿基于 Gitee 官方标签 `3.9.1-G` 的实际 `pom.xml`。该版本使用 Java 21 和 Spring Boot 3.5.13，不使用 Spring Boot 4。

命名说明：`RuoYi-Geek` 只指上游基础项目。本地工程的 Maven 坐标、Java 包、模块目录、类名前缀和配置前缀统一替换为 `zyyyl`，养老业务包使用 `com.zyyyl.nursing`。

## 1. 选型驱动因素

| 编号 | 驱动因素 | 来源 | 对选型的影响 |
| --- | --- | --- | --- |
| 1 | 原项目基于 RuoYi 3.8.8，需升级到现代技术栈 | 项目背景 | 后端以 RuoYi-Geek 为唯一基线 |
| 2 | 前后端接口必须保持不变 | 升级约束 | Controller 路径、请求方法和主要参数不改名 |
| 3 | 已有家属端微信小程序 | 项目现状 | 采用 uni-app 源码重建，复用现有接口 |
| 4 | 已集成 Dify AI 服务 | 原项目 | 保留 WebClient 和 Dify，不引入第二套 AI 框架 |
| 5 | 需要数据库可追踪升级 | 非功能需求 | 使用 RuoYi-Geek 已集成的 Liquibase |
| 6 | 单机部署、毕业设计评审 | 项目规模 | 不引入微服务、注册中心、Kubernetes 和消息中间件 |
| 7 | 面向长者和家属 | UI 需求 | 优先可读性、无障碍和触控友好 |

## 2. 端与运行时边界

| 端 | 运行时 | 构建工具 | 部署形态 | 默认端口 |
| --- | --- | --- | --- | --- |
| 后端服务 | JDK 21 | Maven 3.9+ | JAR 或 Docker | `8080` |
| 后台管理端 | Node.js 20.19+ 或 22.12+ | npm / Vite | Nginx 静态资源 | `80` 或指定端口 |
| 家属端小程序 | 微信开发者工具 | HBuilderX 或 uni-app CLI | 微信小程序 | 不适用 |
| MySQL | MySQL 8.0 推荐 | Liquibase | 本机或容器 | `3306` |
| Redis | Redis 6.2+ | Spring Data Redis | 本机或容器 | `6379` |
| Dify | 现有 Docker 部署 | HTTP / SSE | Linux VM `192.168.100.128` | `80`，API 路径 `/v1` |
| RAGFlow | 现有 Docker 部署 | HTTP API | Linux VM `192.168.100.128` | `9380` |

说明：

- 克隆的 `3.9.1-G` 基准项目默认端口为 `8080`。
- 原 `zzyl` 后端使用 `9901`。迁移后可统一为 `8080`，并与原小程序基础地址保持一致。
- 端口只影响运行和代理配置，不改变任何接口路径。
- 本地开发使用 MySQL 8.0 和 Redis，地址分别为 `192.168.100.168:3306`、`192.168.100.168:6379`。
- Dify 统一编排 AI 对话和知识检索，RAGFlow 只作为 Dify 的知识检索后端。

## 3. 升级对比

| 层级 | 原技术栈（RuoYi 3.8.8 项目） | 新技术栈（RuoYi-Geek） | 升级理由 |
| --- | --- | --- | --- |
| Java | Java 17 | Java 21 | 使用现代 LTS、虚拟线程能力和新语法 |
| 后端框架 | Spring Boot 2.5.15 | Spring Boot 3.5.13 | 进入 Spring Boot 3 维护线，兼容 Jakarta 生态 |
| Spring 核心 | Spring Framework 5.3.33 | 由 Spring Boot 3.5.13 BOM 管理 | 避免手工锁定核心框架版本 |
| 安全框架 | Spring Security 5.7.12 | RuoYi-Geek 内置 Spring Security | 复用权限注解、JWT、登录和限流体系 |
| 持久层 | MyBatis-Plus 3.5.2 | MyBatis-Flex 1.11.5 | 与 RuoYi-Geek 3.9.1-G 基线一致 |
| 数据库迁移 | 手工 SQL 或初始化脚本 | Liquibase | 结构变更可追踪、可回滚 |
| 数据源与连接池 | Druid Spring Boot Starter | Druid Spring Boot 3 Starter | 适配 Spring Boot 3 和 Jakarta |
| 缓存 | Spring Data Redis | Spring Cache + Redis | 使用 Spring Boot 3 自带缓存抽象，按需扩展多级缓存 |
| 接口文档 | Springfox Swagger 3.0.0 | Springdoc 2.8.14 + Knife4j 4.5.0 | 适配 Spring Boot 3，注解更稳定 |
| JWT | JJWT 0.9.1 | JJWT 0.13.0 | 模块化 API，避免旧版 JAXB 兼容问题 |
| 数据库 | MySQL 8 | MySQL 8 | 保持 SQL 和生态兼容 |
| 定时任务 | Quartz | Spring Boot 3.5.13 管理的 Quartz Starter 或 `@Scheduled` | 保留原定时任务模型，按任务复杂度选择 |
| 文件存储 | 自建 OSS 模块 | 本地磁盘 + 阿里云 OSS 可切换适配层 | 保留文件接口，未配置 OSS 时默认本地存储 |
| 管理端 | Vue 3.4 + Vite 5 + Element Plus 2.4.3 | Vue 3.5.34 + Vite 8 + Element Plus 2.14.0 | 组合式 API、构建性能和组件能力提升 |
| 状态管理 | Pinia 2.1.7 | Pinia 3.0.4 | 与新版 Vue 3 基线一致 |
| 路由 | Vue Router 4.2.5 | Vue Router 5.0.6 | 使用基准项目统一路由体系 |
| HTTP | Axios 0.27.2 | Axios 1.16.0 | 安全性、适配器和类型支持改进 |
| 小程序 | 已编译的 uni-app 产物 | uni-app 源码工程 | 可维护、可迭代、可跨端 |
| AI 知识检索 | 原 Dify 单服务 | Dify + RAGFlow | Dify 统一编排，RAGFlow 负责文档检索 |
| AI 调用 | Spring WebClient + Dify | 保留 Spring WebClient + Dify | 接口已存在，避免无意义替换 |

## 4. 后端技术选型

### 4.1 核心框架

| 技术 | 选中版本 | 管理方式 | 选型理由 |
| --- | --- | --- | --- |
| Spring Boot | `3.5.13` | 父 POM BOM | `3.9.1-G` 标签的实际版本 |
| Java | `21` | 父 POM `java.version` | 现代 LTS，满足基准项目要求 |
| MyBatis-Flex | `1.11.5` | 父 POM | 单表 CRUD 和条件构造能力 |
| Druid | `1.2.27` | 父 POM | 连接池、SQL 监控和防注入能力 |
| Liquibase | 由 Spring Boot BOM 管理 | 自动配置 | 数据库迁移版本化 |
| JJWT | `0.13.0` | 父 POM | JWT 签发和验证 |
| Springdoc | `2.8.14` | 父 POM | OpenAPI 3 文档 |
| Knife4j | `4.5.0` | 父 POM | 中文接口调试界面 |
| MySQL 驱动 | `8.3.0` | 父 POM | MySQL 连接 |
| Quartz | 由 Spring Boot 3.5.13 BOM 管理 | 按需引入 | 保留需要持久化和动态调度的任务 |
| Spring WebFlux | 由 Spring Boot BOM 管理 | 显式引入 WebClient 相关依赖 | 保留原有 Dify SSE 流式对话 |

### 4.2 ORM 迁移决策

克隆的 `3.9.1-G` 使用 `mybatis-flex-spring-boot3-starter`，而原养老项目大量使用 MyBatis-Plus。不能同时把两套 ORM 作为主方案，否则会带来事务、分页、插件和映射规则冲突。

选择：

- 以 MyBatis-Flex 作为新项目唯一主 ORM。
- 原 MyBatis XML 查询语句优先原样保留。
- MyBatis-Plus 的 `ServiceImpl`、`LambdaQueryWrapper` 和 `selectPage` 改写为 MyBatis-Flex 等价实现。
- 不改表名、列名和 Controller 接口。

待确认：原项目分页是否全部依赖 PageHelper。若存在，迁移时统一到 RuoYi-Geek 的 `BaseController.startPage` 和 `getDataTable` 体系。

### 4.3 安全与鉴权

继续使用 RuoYi-Geek 内置方案：

- Spring Security 方法级权限。
- `@PreAuthorize("@ss.hasPermi('...')")` 权限标识。
- JWT 加缓存会话。
- `SecurityUtils` 获取当前用户。
- 登录失败锁定和日志记录。

禁止：

- 继续保留原 `zzyl-framework` 的完整安全实现。
- 同时配置两套 `SecurityFilterChain`。
- 在新系统中使用 MD5 存储密码。

### 4.4 缓存和定时任务

| 场景 | 方案 |
| --- | --- |
| 登录会话 | Redis 缓存 |
| 字典和配置 | Spring Cache 抽象，按部署情况选择 Redis 或本地缓存 |
| 热点护理项目 | 短 TTL 本地缓存 |
| 合同状态更新 | Quartz 或 Spring `@Scheduled` 调用现有业务服务 |
| 预约过期更新 | Quartz 或 Spring `@Scheduled` 调用现有业务服务 |
| 护理任务生成 | Quartz 或 Spring `@Scheduled` 调用 `createMonthTask` |

`3.9.1-G` 精简版不包含独立的 Quartz 业务模块。若原任务需要动态修改 Cron 或持久化调度，使用 Spring Boot 3.5.13 BOM 管理的 `spring-boot-starter-quartz`；若任务时间固定，可先使用 `@Scheduled`。定时任务不应直接操作 Mapper，优先复用现有 Service。

### 4.5 后端依赖片段

以下片段用于说明需要显式声明的依赖，不在本文档中直接修改项目文件。

### 5.2 前端目录决策

建议新增养老业务模块：

```text
ruoyi-zyyyl-vue3/
├─ modules/
│  └─ nursing/
│     ├─ package.json
│     └─ src/
│        ├─ api/
│        ├─ components/
│        ├─ views/
│        └─ index.ts
├─ src/
│  ├─ api/
│  ├─ routes/
│  └─ views/
└─ packages/
   ├─ core/
   └─ ui/
```

说明：

- `modules/nursing` 用于养老业务页面和组件。
- `src` 保留应用启动、全局路由和通用页面。
- `packages/core` 的请求、鉴权和路由能力不得复制，直接复用。

## 6. 家属端小程序技术选型

| 技术 | 选择 | 理由 |
| --- | --- | --- |
| 跨端框架 | uni-app + Vue 3 | 原产物基于 uni-app，复用页面和请求逻辑成本低 |
| 开发工具 | HBuilderX 或 uni-app CLI | 与现有开发习惯一致 |
| 页面组织 | 主包 + `subPages` 分包 | 与当前 `app.json` 页面结构一致 |
| 状态管理 | Pinia 或轻量全局 Store | 家属端状态简单，避免过度设计 |
| 请求封装 | 保留统一 `request` 方法 | 继续处理 Token、401 和错误提示 |
| UI | 自定义设计令牌 + uni-app 原生组件 | 减少额外组件库和打包体积 |
| 图标 | SVG 或小程序兼容图标 | 不使用 Emoji 作为功能图标 |

小程序不得把 `Access-Control-Allow-Origin` 当作前端请求头解决方案。跨域由服务端 CORS 或小程序合法域名配置处理。

## 7. 复用映射

| 需求或能力 | 复用方案 | 预计自研量 | 说明 |
| --- | --- | --- | --- |
| 登录与权限 | RuoYi-Geek Security | 低 | 保留原权限标识 |
| 用户、角色、菜单、字典 | RuoYi-Geek system | 低 | 不迁移原系统管理实现 |
| 文件上传 | RuoYi-Geek 文件接口 + 自定义存储适配层 | 低 | 保留文件接口，替换本地存储调用 |
| Excel 导入导出 | Excel 工具和 RuoYi 注解 | 低 | 保留原接口 |
| 数据库迁移 | Liquibase | 低 | 每个变更增加 changeSet |
| 缓存 | Spring Cache + Redis | 低 | 重点缓存字典、配置和热点数据 |
| 定时任务 | Spring Boot Quartz Starter 或 `@Scheduled` | 中 | 迁移任务类和调用方式 |
| 老人、入住、护理业务 | 新建 `nursing` 模块 | 高 | 属于领域业务，不能通用化 |
| AI 对话 | Spring WebClient + Dify | 中 | 保持 SSE 流式响应 |
| 家属端页面 | uni-app 源码 | 中 | 根据现有编译产物重建 |

## 8. 明确排除的技术

| 技术 | 不引入原因 |
| --- | --- |
| Spring Cloud 微服务 | 单机或单机构部署，收益不足 |
| Nacos、Eureka、Consul | 无服务注册和配置中心需求 |
| Kafka、RocketMQ | 当前业务可通过 Quartz、缓存和同步调用完成 |
| Elasticsearch | 数据量不足以支撑额外运维成本 |
| MongoDB | 核心业务关系明确，MySQL 足够 |
| 两套 ORM 并行 | 会导致事务、分页和 SQL 行为不一致 |
| 第二套认证框架 | RuoYi-Geek 已内置完整安全能力 |
| 自研 JWT、密码加密和 Excel 工具 | 已有成熟实现，优先复用 |

## 9. 版本与兼容性结论

本地基准项目已确认以下版本：

| 依赖 | 版本 | 结论 |
| --- | --- | --- |
| Spring Boot | `3.5.13` | 作为统一 BOM |
| Java | `21` | 后端运行时 |
| MyBatis-Flex | `1.11.5` | `mybatis-flex-spring-boot3-starter` |
| Springdoc | `2.8.14` | Spring Boot 3 体系 |
| Knife4j | `4.5.0` | OpenAPI 3 Jakarta starter |
| Druid | `1.2.27` | 使用 `druid-spring-boot-3-starter` |
| JJWT | `0.13.0` | 使用模块化 API |
| Vue | `3.5.34` | 管理端核心 |
| Vite | `8.0.12` | Node 版本必须符合 `engines` |
| Element Plus | `2.14.0` | 管理端组件库 |

本地验证：

- 已从 Gitee 克隆 `https://gitee.com/geek-xd/ruoyi-geek-springboot.git` 的标签 `3.9.1-G`。
- 本地目录为 `ruoyi-zyyyl-springboot3`。
- 工作分支为 `springboot3-work`。
- 使用 JDK 21 执行 `mvn -B -DskipTests compile`，五个 Maven 模块全部编译成功。

风险说明：

- Spring Boot 3 使用 Jakarta API，原 `javax.*` 导入必须迁移。
- MyBatis-Plus 到 MyBatis-Flex 不是简单替换依赖，需要逐模块迁移。
- Jackson 3.0.0-rc2 和 Springdoc 2.8.14 需要在真实启动环境验证序列化和文档生成。
- 本环境未完成外部 Maven Central 和 npm registry 的自动复核，正式开发前必须执行技能提供的 `verify_deps.py` 或等价检查。
