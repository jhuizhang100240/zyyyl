# 智颐云养老系统项目整体修改文档

> 版本：V1.0  
> 迁移方向：原 RuoYi 3.8.8 智能养老系统 → RuoYi-Geek 3.9.1-G（Spring Boot 3.5.13）  
> 目标：保留全部业务能力，保持前后端接口路径不变，统一品牌为“智颐云养老”  
> 实施原则：先建立兼容链路，再迁移业务，最后翻新 UI 和优化数据库

## 1. 改造总览

### 1.1 目标结构

```text
智颐云养老/
├─ ruoyi-zyyyl-springboot3/          # 重命名后的 Spring Boot 3 后端
│  ├─ zyyyl-admin/
│  ├─ zyyyl-common/
│  ├─ zyyyl-framework/
│  ├─ zyyyl-system/
│  └─ zyyyl-modules/
│     ├─ zyyyl-module-quartz/        # 按需引入
│     ├─ zyyyl-module-storage/       # 本地/OSS 双存储适配
│     └─ zyyyl-module-nursing/       # 新增养老业务模块
├─ ruoyi-zyyyl-vue3/
│  ├─ packages/core/
│  ├─ packages/ui/
│  ├─ modules/nursing/              # 新增养老管理端模块
│  └─ src/
├─ zyyyl-family-uniapp/              # 新家属端小程序源码
├─ reference/zzyl/                   # 原系统参考，只读
└─ reference/zzyl-app/               # 原小程序页面参考，只读
```

### 1.2 迁移原则

1. 不复制旧 `zzyl-framework`、`zzyl-common` 和 `zzyl-system`，改用 RuoYi-Geek 对应模块。
2. 养老业务代码进入独立 `zyyyl-module-nursing`。
3. Controller 路径、请求方法、参数名和响应字段不改名。
4. 数据库表名和既有列名不因包名迁移而改名。
5. 品牌信息统一修改，但不得影响接口和数据库标识。
6. 所有数据库变更通过 Liquibase 提交。
7. 每迁移一个业务域，立即执行接口回归，不等到最后统一联调。

## 2. 代码迁移步骤

### 2.1 第 0 步：备份与环境检查

```powershell
git -C ruoyi-zyyyl-springboot3 status --short --branch
git -C ruoyi-zyyyl-springboot3 branch --show-current

java -version
mvn -version
node -v
npm -v
```

当前本地后端克隆仍位于待重命名的 `ruoyi-geek-springboot3`，工作分支为 `springboot3-work`，并停在标签 `3.9.1-G` 对应的提交。执行 `plan/全局重命名-plan.md` 后使用 `ruoyi-zyyyl-springboot3`。

要求：

- JDK 21。
- Maven 3.9 或兼容版本。
- Node.js 20.19+ 或 22.12+。
- MySQL 与 Redis 可连接。
- 原数据库和上传目录完成备份。

数据库备份：

```bash
mysqldump -u root -p --single-transaction --routines --triggers zyyyl > zyyyl_backup.sql
```

上传目录备份：

```text
D:/ruoyi/uploadPath/
D:/zyyyl/uploadPath/
```

待确认：原系统文件实际存储位置和对象存储地址。

### 2.2 第 1 步：创建养老业务模块

在 RuoYi-Geek 根 POM 的 `<modules>` 中增加：

```xml
<module>zyyyl-modules/zyyyl-module-nursing</module>
```

新建模块目录：

```text
zyyyl-modules/zyyyl-module-nursing/
├─ pom.xml
└─ src/main/
   ├─ java/com/zyyyl/nursing/
   │  ├─ config/
   │  ├─ controller/
   │  ├─ domain/
   │  ├─ dto/
   │  ├─ mapper/
   │  ├─ service/
   │  ├─ service/impl/
   │  ├─ job/
   │  └─ vo/
   └─ resources/
      ├─ mapper/nursing/
      └─ db/changelog/
```

模块依赖只引入必要内容：

```xml
<dependencies>
    <dependency>
        <groupId>com.zyyyl</groupId>
        <artifactId>zyyyl-common</artifactId>
        <version>${zyyyl.version}</version>
    </dependency>
    <dependency>
        <groupId>com.zyyyl</groupId>
        <artifactId>zyyyl-framework</artifactId>
        <version>${zyyyl.version}</version>
    </dependency>
    <dependency>
        <groupId>com.zyyyl</groupId>
        <artifactId>zyyyl-system</artifactId>
        <version>${zyyyl.version}</version>
    </dependency>
</dependencies>
```

具体依赖以 RuoYi-Geek 现有模块写法为准，避免重复声明 BOM 已管理的版本。

### 2.3 第 2 步：包名和模块映射

推荐将养老业务代码包名统一迁移到 `com.zyyyl.nursing`，使 RuoYi-Geek 的 `scanBasePackages = "com.zyyyl"` 可以自动扫描。

| 原位置 | 新位置 | 处理方式 |
| --- | --- | --- |
| `zzyl/zzyl-admin` | `zyyyl-admin` | 合并启动类已有的通用 Controller |
| `zzyl/zzyl-framework` | `zyyyl-framework` | 不迁移，改用 Geek 安全、缓存、数据源和 Web 配置 |
| `zzyl/zzyl-system` | `zyyyl-system` | 不迁移，改用 Geek 系统管理实现 |
| `zzyl/zzyl-common` | `zyyyl-common` | 公共工具优先使用 Geek 实现 |
| `zzyl/zzyl-nursing-platform` | `zyyyl-modules/zyyyl-module-nursing` | 包名迁移为 `com.zyyyl.nursing` |
| `zzyl/zzyl-quartz` | `zyyyl-modules/zyyyl-module-quartz` | 保留任务类，调用新业务 Service |
| `zzyl/zzyl-generator` | 暂不迁移 | 首期不启用代码生成模块 |
| `zzyl/zzyl-oss` | `zyyyl-modules/zyyyl-module-storage` | 本地磁盘和阿里云 OSS 双适配，配置缺失时回退本地 |

`3.9.1-G` 精简标签只包含 `zyyyl-admin`、`zyyyl-common`、`zyyyl-framework` 和 `zyyyl-system`。`zyyyl-module-quartz`、`zyyyl-module-storage` 和 `zyyyl-module-nursing` 都需要按实际业务迁移后新增。

包名映射：

| 原包名 | 新包名 |
| --- | --- |
| `com.zzyl.nursing` | `com.zyyyl.nursing` |
| `com.zzyl.common` | `com.zyyyl.common` |
| `com.zzyl.framework` | `com.zyyyl.framework` |
| `com.zzyl.system` | `com.zyyyl.system` |
| `com.zzyl.quartz` | `com.zyyyl.quartz` |
| `com.zzyl.generator` | `com.zyyyl.generator` |
| `com.zzyl.oss` | 删除，改用 `zyyyl-module-storage` 存储接口 |

禁止：

- 使用全局正则把数据库字段 `zzyl` 一并替换。
- 修改 Controller 注解中的访问路径。
- 把 `com.zyyyl` 全局替换回 `com.zzyl`。
- 同时保留两套同功能工具类和安全配置。

### 2.4 第 3 步：迁移公共基础能力

| 原实现 | 新实现 |
| --- | --- |
| 原 JWT 工具 | RuoYi-Geek `TokenService` |
| 原 Security 配置 | RuoYi-Geek `SecurityConfig` |
| 原登录服务 | RuoYi-Geek `SysLoginService` |
| 原权限注解 | RuoYi-Geek `@PreAuthorize("@ss.hasPermi(...)")` |
| 原分页控制 | RuoYi-Geek `BaseController.startPage` |
| 原文件上传 | RuoYi-Geek `FileController` 和存储插件 |
| 原异常处理 | RuoYi-Geek 全局异常处理 |
| 原日志注解 | RuoYi-Geek `@Log` |
| 原字典缓存 | Geek 缓存和字典工具 |

迁移检查：

- `javax.*` 改为 `jakarta.*`。
- JJWT 0.9.x API 改为 0.13.0 API。
- `SecurityFilterChain` 配置使用基准项目写法。
- CORS 只配置一次。
- `@Anonymous` 等匿名接口按 Geek 方式标注。

### 2.5 第 4 步：迁移数据访问层

1. 原 Mapper 接口迁移到 `com.zyyyl.nursing.mapper`。
2. 原 XML 移至 `src/main/resources/mapper/nursing`。
3. XML namespace 更新为新 Mapper 全限定名。
4. MyBatis-Plus 的 `BaseMapper` 改为 MyBatis-Flex Mapper。
5. `ServiceImpl` 改为 MyBatis-Flex 的 `ServiceImpl`。
6. `LambdaQueryWrapper` 和 `LambdaUpdateWrapper` 改写为 QueryWrapper。
7. 原分页统一使用 Geek `BaseController` 或 MyBatis-Flex 分页。

迁移顺序：

```text
elder -> facility -> check-in -> contract -> health
-> nursing level/project/plan -> nursing task
-> reservation -> family member -> AI
```

每迁移一个模块后执行：

```bash
mvn -pl zyyyl-modules/zyyyl-module-nursing -am test
```

### 2.6 第 5 步：迁移定时任务

原任务类：

| 任务 | 迁移方式 |
| --- | --- |
| `ContractJob.updateContractStatus` | 调用 Geek 护理模块 Service |
| `ReservationJob.updateReservationStatus` | 调用 Geek 护理模块 Service |
| `CreateNursingTaskJob.createNursingTaskJob` | 调用护理任务生成服务 |

要求：

- 创建人和更新人回退到系统账号。
- 任务幂等，重复执行不生成重复数据。
- 任务异常写入日志并可重试。

## 5. 数据库迁移实施

### 5.1 新增 Liquibase 文件

```text
zyyyl-admin/src/main/resources/db/changelog/changelog-5-zyyyl-migration.xml
```

在主 changelog 中引入：

```xml
<include file="db/changelog/changelog-5-zyyyl-migration.xml"
         relativeToChangelogFile="true"/>
```

### 5.2 迁移顺序

1. 创建新表和新增字段。
2. 导入基础字典和脱敏演示数据，不导入真实老人、家属和合同记录。
3. 回填新增字段。
4. 验证数据一致性。
5. 增加唯一约束。
6. 增加组合索引。
7. 切换代码读取新结构。
8. 保留旧字段一个版本周期。

### 5.3 回滚策略

- 每个 changeSet 提供 `rollback`。
- 数据迁移前保存表行数和校验结果。
- 应用回滚前先确认 Liquibase 是否可逆。
- 唯一索引回滚只删除索引，不删除业务数据。

## 8. 风险控制

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| MyBatis-Plus 与 MyBatis-Flex 差异大 | 业务代码迁移量大 | 按模块迁移，保留 XML，优先回归核心查询 |
| Spring Boot 3 与旧依赖冲突 | 启动失败 | 以 RuoYi-Geek 3.9.1-G 的 Spring Boot 3.5.13 BOM 为准，不手工覆盖核心依赖 |
| 旧数据库存在脏数据 | 唯一索引无法创建 | 先统计、备份、去重，再执行约束 |
| 小程序源码缺失 | 只能重建，周期增加 | 提前确认源码；没有源码时按页面逐页重建 |
| Dify 服务不可用 | AI 功能失败 | 后端提供明确错误，非 AI 功能不受影响 |
| 品牌全局替换误伤代码 | 接口或数据库异常 | 使用清单式替换，禁止全仓库盲目替换 |
| 旧文件和图片无法访问 | 页面缺图 | 迁移时校验文件，生成缺失清单 |
| 时间不足 | 功能未完成 | 先保原业务和接口，再做新增提醒和 UI 动画 |
